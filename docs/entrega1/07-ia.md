# Experiencia con IA generativa

Codex se utilizó en distintas fases del trabajo. Primero sirvió para interpretar las instrucciones y distinguir lo que correspondía a la primera entrega de lo que se desarrollará después. La orientación inicial daba demasiado peso a una aplicación completa. La indicación «una pantalla por cada funcionalidad» llevó a acotar el spike y a centrarse en comprobar las conexiones entre sus componentes.

Después se trabajó sobre las historias de usuario y sus escenarios. Se mantuvo la separación entre usuarios, lugares, vehículos, rutas, preferencias y persistencia. Los costes de combustible y electricidad se trataron por separado para revisar sus unidades. En los escenarios de rutas se sustituyeron las expectativas de distancia fija por comprobaciones sobre el resultado recibido, porque una API real puede cambiar el trayecto que devuelve.

Para el código y las interfaces se conservaron las tecnologías y los adaptadores existentes. Se descartaron el copiloto y las simulaciones porque no eran necesarios para la iteración 0. Las propuestas se comprobaron con pruebas y con el navegador. Se corrigieron las etiquetas de los desplegables y un error de Leaflet al cambiar de pantalla durante una animación.

La herramienta ayudó a redactar borradores, organizar los escenarios y localizar errores. Su principal inconveniente fue ampliar el alcance más de lo necesario. Además, los datos simulados permiten comprobar cálculos y errores, pero no demuestran que un servicio público esté disponible. Se mantuvo una interfaz sencilla y se distinguieron ambos tipos de prueba. Para las siguientes iteraciones conviene definir primero las pruebas y contrastar las propuestas con el enunciado y con el código.


## Ejemplos de la revisión del 15 de octubre

Los siguientes fragmentos pertenecen a esta revisión. La descripción de cada respuesta es un resumen, no una transcripción completa.

**Revisión de documentos e historias**

Se pidió revisar los documentos y comprobar si había demasiadas historias. El mensaje incluía el fragmento «historias usuario bien». Codex contrastó el catálogo con los cuatro PDF docentes. Su respuesta resumida fue mantener las 26 historias y justificar las dos separaciones respecto a las 24 propuestas. Esta revisión ayudó a explicar el alcance. El recuento por sí solo no demuestra que las historias estén bien estimadas ni aprobadas por el profesorado.

**Revisión de la redacción**

La petición incluyó «lenguaje natural academico no complejo». Codex propuso frases más cortas y sustituyó expresiones como revocación y atomicidad por explicaciones de lo que debe ocurrir. Se conservaron los términos del enunciado y los identificadores técnicos necesarios. El cambio facilita la lectura, pero el equipo debe comprobar que no se pierda precisión al simplificar.

**Comprobación de las propuestas**

Durante la revisión, una prueba reprodujo un error de acceso con contraseñas que tenían espacios exteriores. El registro los conservaba y el acceso los eliminaba. Se corrigió el acceso y se repitió la prueba. También se añadió una comprobación del guardado interrumpido antes de confirmar la transacción. Estos casos muestran por qué una explicación generada debe contrastarse con el código y con una ejecución.

\subsection*{HU-01. Registrar una cuenta}

\textbf{Requisito:} R1\par

\textbf{Historia:} Como persona no registrada quiero crear una cuenta para utilizar los servicios de movilidad.\par

\subsubsection*{Reglas de dominio aplicables}

\textbf{RD-01:} El correo electrónico debe estar normalizado.\par

\textbf{RD-02:} El correo electrónico debe ser único.\par

\textbf{RD-03:} El correo electrónico puede tener como máximo 254 caracteres.\par

\textbf{RD-04:} El nombre debe tener entre 1 y 70 caracteres.\par

\textbf{RD-05:} La contraseña debe tener entre 10 y 128 caracteres.\par

\textbf{RD-06:} Una operación inválida no debe modificar el estado confirmado.\par

\subsubsection*{E-01-V --- Escenario válido · Prueba PA-01-V}

\textbf{Justificación:} acredita el alta de una cuenta utilizando datos que cumplen las reglas de dominio.\par

\textbf{Given:} hay conexión con el servidor, el almacenamiento está disponible y no existe la cuenta con correo ana@example.com.\par

\textbf{When:} una persona no registrada intenta crear una cuenta con nombre Ana, correo ana@example.com y contraseña RutaSegura2026.\par

\textbf{Then:} se crea una única cuenta para Ana, se devuelve su identificador y la contraseña no aparece en la respuesta. El correo ana@example.com queda registrado y no se modifica ninguna otra cuenta.\par

\subsubsection*{E-01-I1 --- Escenario inválido · Prueba PA-01-I}

\textbf{Justificación:} comprueba que no se permite crear una segunda cuenta con un correo ya registrado.\par

\textbf{Given:} hay conexión con el servidor y ya existe una cuenta con correo ana@example.com.\par

\textbf{When:} una persona intenta crear una nueva cuenta con nombre Ana2, correo ana@example.com y contraseña OtraClave2026.\par

\textbf{Then:} se rechaza la operación por correo duplicado y el estado de las cuentas no se modifica.\par

\clearpage\subsection*{HU-03. Cerrar sesión}

\textbf{Requisito:} R1\par

\textbf{Historia:} Como usuario autenticado quiero cerrar mi sesión para impedir el acceso posterior desde ella.\par

\subsubsection*{Reglas de dominio aplicables}

\textbf{RD-11:} Cerrar una sesión debe revocar su capacidad de autenticar peticiones posteriores.\par

\textbf{RD-12:} El cierre de sesión conserva los contenidos del usuario.\par

\textbf{RD-13:} Cerrar un token inexistente o volver a cerrar uno revocado no concede acceso ni altera otras sesiones.\par

\textbf{RD-14:} La revocación debe comprobarse mediante una petición posterior, además del cambio de pantalla.\par

\textbf{When:} cierra S1 y vuelve a solicitar sus datos con ese token.\par

\textbf{Given:} el token S0 no corresponde a ninguna sesión.\par

\textbf{When:} se solicita cerrar S0 y consultar datos con S0.\par

\textbf{Then:} no se concede acceso ni se modifican otras sesiones.\par
